# Рабочий процесс проекта

Проект ведётся небольшой командой из двух участников. Поэтому процесс должен быть лёгким, но не хаотичным.

## 1. Базовый цикл

1. Выбрать одну пользовательскую ценность.
2. Записать критерии приёмки.
3. Проверить, входит ли задача в текущий этап.
4. Реализовать минимальный вертикальный срез.
5. Добавить тесты критической логики.
6. Проверить локально и на реальном устройстве, когда это применимо.
7. Обновить документацию или ADR.
8. Зафиксировать результат маленьким коммитом.

## 2. Ветки

Рекомендуемый формат:

```text
main
feature/<короткое-название>
fix/<короткое-название>
docs/<короткое-название>
spike/<исследование>
```

Долгоживущие ветки не создаются. Изменения должны быть достаточно малы, чтобы их можно было проверить за одну рабочую сессию.

## 3. Коммиты

Предпочтительный формат:

```text
feat: add activity sync contract
fix: prevent duplicate energy reward
docs: clarify adaptive goal formula
test: cover activity delta calculation
refactor: isolate expedition progression
```

## 4. Definition of Done

Задача считается завершённой, когда:

- критерии приёмки выполнены;
- код собирается;
- критическая бизнес-логика покрыта тестом;
- отсутствуют секреты в репозитории;
- ошибки обрабатываются явно;
- API и документация не противоречат реализации;
- для изменения архитектурного решения добавлен ADR;
- мобильная функция проверена хотя бы на одном реальном устройстве, если она зависит от системных API.

## 5. Взаимодействие с ИИ-партнёром

Для продолжения работы передаётся актуальный архив проекта, ссылка на подключённый репозиторий либо конкретные изменённые файлы.

Полезный формат постановки задачи:

```text
Контекст:
Цель:
Текущее поведение:
Ожидаемое поведение:
Ограничения:
Критерии приёмки:
Файлы/архив:
```

ИИ-партнёр может подготовить код, diff, архив, тесты, ревью и документацию в рамках текущей сессии. Локальный запуск на физических устройствах и финальная приёмка остаются за владельцем проекта.

## 6. Правило против переусложнения

Перед добавлением новой библиотеки, сервиса, очереди, кэша или слоя необходимо ответить:

1. Какую текущую измеренную проблему это решает?
2. Почему простое решение недостаточно?
3. Как удалить эту зависимость, если гипотеза не подтвердится?

Если убедительного ответа нет, решение откладывается.
